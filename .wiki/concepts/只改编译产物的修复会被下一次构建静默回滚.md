## 一个「修好了」的假象

2026-10-15 的会话里修好并验证过一个 bug（`wiki_drill` 模式 B 在有双链的页上输出 `message: undefined`）。修复被写进了 **`lib/drill.js`（编译产物）**，验证通过、当轮结论是「修复完整」。但这份修复**从未落到 `src/drill.ts`**。

下一轮无关改动（改 `src/trigger.ts`）跑了一次 `npm run build`，tsc 从 src 重新生成 lib —— 修复被**静默回滚**，没有任何报错、没有任何 diff 提示。

## 时间戳证据

| 文件 | mtime | 内容 |
|---|---|---|
| `src/drill.ts` | 2026-09-28 | 仍是 `message: empty ? '…' : undefined`（bug 原样） |
| `lib/drill.js` | 2026-10-15 00:35 | 曾被手工修好，随后被 build 覆盖回 bug 原样 |

三处（`src`、本仓库 `lib`、已安装副本）在事后检查时**都是 bug 原样**，与「已修复」的结论直接矛盾。

## 这条 bug 本身：`undefined` 不是合法 JSON 值

```
message: empty ? '该页…没有出链也没有入链可下钻。' : undefined   // ✗ 有双链时值为 undefined
...(empty ? { message: '该页…' } : {})                          // ✓ 无话可说时字段「不存在」
```

宿主工具网关（`@deepseek-ai/dsh-util-values` 的 `isJsonValue`）把 `undefined` 判为非法 JSON 值，**整条工具输出被拒**，模型只看到 `value is not lossless JSON`——不是这一句文案坏了，是整个 `wiki_drill` 的返回值报废。

**为什么此前所有测试都绿：**
- lib 层断言 `message` 文案的用例全绿（文案确实是对的）；
- schema 校验也过 —— `undefined` 不是类型错误，`validateJsonSchemaValue` 不查它；
- 只有真跑宿主网关才炸。

回归防线因此必须是**两件事**：① 断言「无话可说时 `message` 键不存在」（而不是值为 undefined）；② 输出做一次无损 JSON 往返（`JSON.parse(JSON.stringify(out))`）并深比较。深度扫描 `undefined` 的辅助函数能把定位精确到 `$.message`。

## 纪律

1. **永远改 `src/`，改完构建。** 直接改 `lib/` 下的编译产物 = 给自己埋一颗「下次 build 静默回滚」的雷，而且回滚无声。
2. **验证要在正确的层做。** 「文案对」不等于「输出合法」；工具输出这类跨进程契约，要在**宿主网关的同款判定**下验证（无损 JSON 往返），不能只验字段值。
3. **时间戳是对账「改了没有」的硬证据。** 怀疑修复没生效时，先比 `src` 与 `lib` 的 mtime，再比内容——本例就是靠 mtime 顺序（src 早于 lib）锁定了「只改了产物」。
4. **这类修复在 git 里完全不可见。** 本仓库 `.gitignore` 第 2 行就是 `lib/` —— 编译产物不入版本控制。于是「只改了 lib」这件事在 `git status` / `git diff` 里**没有任何痕迹**：代码评审看不见、提交记录看不见、回滚也回不出来。它不是「忘了提交」，而是**版本控制根本无法表达**这一类改动。
